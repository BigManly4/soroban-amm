# PR Title: fix: resolve issues #498, #499, #500, #501 across contracts and SDK

## Problem Being Solved

### Issue #498: Storage backend mismatch in `concentrated_liquidity`
In `contracts/concentrated_liquidity/src/lib.rs`, `burn_position_by_token_id` and `cleanup_nft_if_closed` attempted to read position data via `env.storage().instance().get(...)` using `DataKey::Position(...)`. However, every write path for `Position` (mint, modify, burn_position_core, collect_fees_core) stores positions in `.persistent()` storage. Because instance storage never contained `DataKey::Position`, these lookups returned `None`. This caused `closed` to evaluate to `true` even on partial liquidity burns, burning the receipt NFT, deleting forwarding indexes (`PositionNftToken` and `NftTokenToPosition`), and breaking downstream NFT-keyed accesses as well as allowing original providers to bypass NFT ownership.

### Issue #499: Missing guards in `amm::remove_liquidity_one_sided`
In `contracts/amm/src/lib.rs`, `remove_liquidity_one_sided` performs an internal constant-product swap of the non-chosen token into the target `token_out`, moving the pool's reserves and price. However, unlike `swap`, `swap_exact_out`, `flash_loan`, and `swap_fot`, `remove_liquidity_one_sided` did not invoke `Self::check_circuit_breaker(&env)?` or `Self::check_oracle_deviation(...)`. This allowed large one-sided withdrawals to move the pool price past circuit breaker or oracle deviation thresholds in a single transaction without triggering protection guards.

### Issue #500: Stale `BatchOpenedAt` in `batch_auction::settle_batch`
In `contracts/batch_auction/src/lib.rs`, `settle_batch` only refreshed `DataKey::BatchOpenedAt` to `now` if `remaining.is_empty()` after execution. When more orders were pending than the `max_orders` cap, leftover orders remained in queue and `BatchOpenedAt` stayed set to its old timestamp. Consequently, any subsequent order submitted joined `PendingOrders` and could be settled immediately in the next `settle_batch` call without waiting through a full batch window, compromising the anti-sandwich window guarantee.

### Issue #501: Trailing `referrer` parameter mismatch in `amm-sdk`
In `contracts/amm-sdk/src/client.rs`, `AmmPoolInterface` declared `swap` and `swap_exact_out` with a trailing `referrer: Option<Address>` parameter. The deployed `amm` pool entry points (`amm::AmmPool::swap` and `amm::AmmPool::swap_exact_out`) do not take a referrer argument. Cross-contract calls generated by `#[contractclient]` failed at the XDR host level due to parameter list mismatches whenever `execute_swap` or `execute_swap_exact_out` were invoked.

## Implemented Solution

1. **Fix #498**: Updated lines 1286 and 1577 of `contracts/concentrated_liquidity/src/lib.rs` to read `DataKey::Position` using `env.storage().persistent()` matching all other position call sites. Added unit test `test_partial_burn_by_token_id_preserves_nft_and_indexes`.
2. **Fix #499**: Updated `remove_liquidity_one_sided` in `contracts/amm/src/lib.rs` to call `Self::check_circuit_breaker(&env)?;` prior to deducting withdrawn reserves, and `Self::check_oracle_deviation(&env, &token_swap, &token_out, amount_swap, swap_output)?;` after computing the internal swap output. Added unit test `test_remove_liquidity_one_sided_circuit_breaker`.
3. **Fix #500**: Updated `settle_batch` in `contracts/batch_auction/src/lib.rs` to set `DataKey::BatchOpenedAt` to `now` unconditionally on every settlement execution. Added unit test `test_partial_settlement_refreshes_batch_opened_at`.
4. **Fix #501**: Removed `referrer: Option<Address>` parameter from `AmmPoolInterface::swap`, `AmmPoolInterface::swap_exact_out`, `AmmPoolSdk::execute_swap`, and `AmmPoolSdk::execute_swap_exact_out` in `contracts/amm-sdk/src/client.rs`. Updated example usage in `contracts/amm-sdk/src/examples/basic_swap.rs`.

## Technical Decisions Made
- **Storage Backend Consistency**: Aligned all `DataKey::Position` accesses to use `.persistent()` storage across the entire `concentrated_liquidity` contract.
- **Guard Sequence**: Placed `check_circuit_breaker` prior to reserve mutation to capture intra-sequence price movements, and `check_oracle_deviation` immediately after calculating `swap_output` before transferring tokens.
- **Batch Window Guarantee**: Ensured every settlement execution resets `BatchOpenedAt` so any remaining or newly arriving orders must wait out a full window period.
- **SDK Contractclient Alignment**: Removed `referrer` parameter from `swap` and `swap_exact_out` to strictly mirror the deployed contract entry point signatures.
